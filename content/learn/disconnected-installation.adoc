= Deploy a validated pattern in a disconnected network

A disconnected network is an infrastructure isolated from external internet access.
Deploying {solution-name-upstream} in this environment requires mirroring container images, configuring internal registries, and adjusting pattern configuration files.

This guide describes deploying the {mcg-pattern} on {ocp} 4.19 in a disconnected network.
The same approach applies to other validated patterns, although the required images and Operators vary by pattern.

.Prerequisites

* One or more {ocp} clusters deployed in a disconnected network.
* An OCI-compliant registry accessible from the disconnected network, referred to as `registry.internal.disconnected.net` in this guide.
* A Git repository accessible from the disconnected network.
* (Optional) A virtual machine (VM) in the disconnected network to run commands.

[NOTE]
====
Deploying {ocp} in a disconnected network is outside the scope of this guide. For details, see the link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.19/html-single/disconnected_environments/index#about-installing-oc-mirror-v2[{ocp} disconnected environments documentation] for details.
====

[id="mirror-images"]
== 1. Mirror required container images to an internal registry

Mirror all required container images to the internal registry.
The specific images you mirror depend on the pattern, the {ocp} version, and the required Operators.

=== Generate an ImageSetConfiguration

Use `patternizer airgap bootstrap` (or `./pattern.sh make airgap-bootstrap`) to discover Operators, Helm charts, and container images from the pattern values files and generate an oc-mirror v2 `imagesetconfig.yaml` plus helper artifacts.

.Procedure

. From an absolute path to the pattern repository, or from a Git URL, generate bootstrap artifacts:
+
[source,terminal]
----
# Absolute path
pattern airgap bootstrap /path/to/multicloud-gitops \
  --ocp-version 4.19 \
  --registry registry.internal.disconnected.net \
  --platform \
  --output-dir /path/to/airgap-out

# Or clone from Git
pattern airgap bootstrap https://github.com/validatedpatterns/multicloud-gitops \
  --git-ref main \
  --ocp-version 4.19 \
  --registry registry.internal.disconnected.net \
  --output-dir /path/to/airgap-out

# Or via the pattern Makefile (from inside a local checkout)
./pattern.sh make airgap-bootstrap \
  AIRGAP_OCP_VERSION=4.19 \
  AIRGAP_REGISTRY=registry.internal.disconnected.net
----
+
Artifacts written to `airgap-out/` (or `AIRGAP_OUTPUT_DIR`):
+
* `imagesetconfig.yaml` — oc-mirror v2 ImageSetConfiguration
* `values-disconnected.yaml` — catalog source and `helmRepoUrl` overlay
* `mirror-commands.sh` — example `oc mirror --v2` commands
* `CHECKLIST.md` — pull secrets, Git, CatalogSources, and Vault/ESO secrets checklist

. Review `CHECKLIST.md` and confirm discovered chart images (for example Vault `registry.connect.redhat.com/hashicorp/vault:<tag>` from the resolved chart values). Adjust only if your site needs extras.
+
Do **not** pass `--skip-oci-resolve` on a connected bastion — that skips live chart version resolution and operand image discovery.

. (Optional) After a mirror run, parse oc-mirror logs for skipped `oci://` related images:
+
[source,terminal]
----
pattern airgap parse-mirror-log /path/to/oc-mirror.log
----

. Example generated structure (Multicloud GitOps) looks like:
+
[source,yaml]
----
kind: ImageSetConfiguration
apiVersion: mirror.openshift.io/v2alpha1
mirror:
  platform:
    graph: true
    channels:
    - name: stable-4.19
      type: ocp
  operators:
  - catalog: registry.redhat.io/redhat/redhat-operator-index:v4.19
    packages:
      - name: advanced-cluster-management
        channels:
          - name: release-2.16
      - name: multicluster-engine
      - name: openshift-gitops-operator
  - catalog: registry.redhat.io/redhat/community-operator-index:v4.19
    packages:
      - name: patterns-operator
  additionalImages:
  - name: registry.redhat.io/ubi9/ubi-minimal:latest
  - name: registry.connect.redhat.com/hashicorp/vault:1.21.4-ubi
  - name: registry.access.redhat.com/ubi10/httpd-24:10.0-1755779646
  - name: ghcr.io/external-secrets/external-secrets:v0.10.2-ubi
  - name: quay.io/validatedpatterns/acm:0.1.17
  - name: quay.io/validatedpatterns/clustergroup:0.9.41
  - name: quay.io/validatedpatterns/golang-external-secrets:0.1.5
  - name: quay.io/validatedpatterns/hashicorp-vault:0.1.6
  - name: quay.io/validatedpatterns/utility-container:latest
  - name: quay.io/validatedpatterns/imperative-container:v1
  - name: quay.io/validatedpatterns/pattern-install:0.0.11
----

. Run the mirror command and specify a local cache directory and the target registry:
+
[source,terminal]
----
oc mirror --config=/var/cache/oc-mirror/imageset-config.yaml \
    --workspace file:///var/cache/oc-mirror/workspace \
    docker://registry.internal.disconnected.net --v2 <1>
----
<1> The example uses the `--v2` flag to mirror images.
+
When mirroring completes, `oc mirror` generates resource files in the `/var/cache/oc-mirror/workspace/working-dir/cluster-resources` directory.

. Apply the generated resource files to the cluster so that the cluster can resolve images from the internal registry:
+
[source,terminal]
----
cd /var/cache/oc-mirror/workspace/working-dir/cluster-resources
oc apply -f cs-community-operator-index-v4-19.yaml \
  cs-redhat-operator-index-v4-19.yaml idms-oc-mirror.yaml \
  itms-oc-mirror.yaml
----
+
[IMPORTANT]
====
The catalog source names generated by the `oc mirror` command, such as `cs-redhat-operator-index-v4-19`, are required to configure the pattern values files. Do not change these names.
====

[id="configure-pattern"]
== 2. Configure the pattern for disconnected use

Update the pattern values files to reference the mirrored catalog sources and the internal Helm chart registry.
Verify that the `origin` remote for the local Git clone points to the disconnected Git server by running the `git remote -v` command.

TIP: Merge the generated `values-disconnected.yaml` from `airgap bootstrap` into your pattern values (or commit it as an overlay) so catalog source names and `helmRepoUrl` match the oc-mirror output.

.Procedure

. In the `values-global.yaml` file, point the Helm chart repository to the internal registry and configure operator sources:
+
[source,yaml]
----
main:
  multiSourceConfig:
    enabled: true
    clusterGroupChartVersion: "0.9.*"
    helmRepoUrl: registry.internal.disconnected.net/validatedpatterns
  patternsOperator:
    source: cs-community-operator-index-v4-19 <1>
  gitops:
    operatorSource: cs-redhat-operator-index-v4-19 <1>
----
<1> The catalog source names must match the generated catalog sources from the `oc mirror` command.

. In the `values-hub.yaml` file, configure operator sources for hub-specific components:
+
[source,yaml]
----
acm:
  mce_operator:
    source: cs-redhat-operator-index-v4-19

clusterGroup:
  subscriptions:
    acm:
      name: advanced-cluster-management
      namespace: open-cluster-management
      channel: release-2.14
      source: cs-redhat-operator-index-v4-19
----

. Commit and push these changes to the disconnected Git server.

[id="deploy-pattern"]
== 3. Deploy the pattern

After mirroring images and configuring the pattern, deploy the pattern from a machine that has access to the disconnected cluster and the Git repository.

.Procedure

* Point the installation program to the mirrored Helm chart registry and deploy the pattern:
+
[source,terminal]
----
export PATTERN_DISCONNECTED_HOME=registry.internal.disconnected.net/validatedpatterns
./pattern.sh make install
----
+
The cluster converges to the specified state and the pattern installs.

[id="disconnected-secrets"]
== 4. Secrets in a disconnected network

Do not put secrets in the ImageSetConfiguration. Treat credentials as three separate planes:

* *Mirror-host pull secrets* — On the connected bastion running `oc mirror`, configure `auth.json` for `registry.redhat.io`, `registry.connect.redhat.com`, `quay.io`, `ghcr.io`, and any other source registries.
* *Cluster registry pull* — Trust the internal registry CA and apply IDMS/ITMS from oc-mirror so nodes pull from the mirror.
* *Pattern application secrets* — Keep Vault + External Secrets Operator (ESO). Mirror their Operators and operand images, then seed secrets *inside* the air gap:

[source,terminal]
----
# On a trusted host that can reach the disconnected cluster
cp values-secret.yaml.template ~/values-secret.yaml
# Edit secrets; prefer onMissingValue: generate where possible
export PATTERN_DISCONNECTED_HOME=registry.internal.disconnected.net/validatedpatterns
./pattern.sh make load-secrets
----

Never commit a real `values-secret.yaml` to Git.
External secret backends that require egress (cloud secret managers, SaaS Vault) will not work offline — use in-cluster Vault.

See also link:../secrets-management-in-the-Validated-Patterns-framework/[Secrets management in the Validated Patterns framework].

== Adapting this guide for other patterns

When deploying a different pattern in a disconnected network:

* Run `pattern airgap bootstrap` (or `./pattern.sh make airgap-bootstrap`) in that pattern repository to regenerate `imagesetconfig.yaml`.
* Review `CHECKLIST.md` for pattern-specific Operators, charts, managed/spoke clusters, and secrets.
* Merge `values-disconnected.yaml` and confirm CatalogSource names match the oc-mirror output.
* Update site-specific values files if subscriptions use custom `source:` fields.
